# MemoryKeeper Information Architecture

> 사진 관리 프로그램이 아니라, **추억을 탐험하는 플랫폼**.

이 문서는 MemoryKeeper의 **정보 구조(IA)** 를 고정한다.  
**기능을 추가하지 않는다. UI를 크게 변경하지 않는다.**  
역할·탐색 구조·화면 책임만 정의한다.

표현·카피·레이아웃 원칙은 `Docs/UX_PHILOSOPHY.md`를 따른다.

---

## 1. 제품 정의

MemoryKeeper는 사진을 **저장·정리하는 도구**가 아니다.  
사용자가 **다양한 방법으로 추억을 탐험**하는 플랫폼이다.

| 아님 | 임 |
|---|---|
| 파일 관리자 | 기억 탐험 플랫폼 |
| 통계 Dashboard | 발견 · 회상 · 감상 |
| 단일 검색창 앱 | 다섯 가지 탐색 방식의 집합 |

키워드: **탐험 · 발견 · 회상 · 감상 · 연결**

---

## 2. 다섯 가지 기억 탐색 방식

모든 주요 화면은 아래 **다섯 가지 중 하나**를 담당한다.

| # | 탐색 방식 | 사용자 의도 | 담당 화면 | 한 줄 역할 |
|---|---|---|---|---|
| ① | **시간** | 언제였지? | 여행기록 | 시간을 따라 기억을 탐험한다 |
| ② | **장소** | 어디였지? | 방문지도 | 장소를 따라 기억을 탐험한다 |
| ③ | **여행** | 그 여행 다시 보고 싶다 | 여행기록 | 여행(Story) 단위로 기억을 탐험한다 |
| ④ | **사진** | 그 사진 다시 보고 싶다 | 사진첩 | 사진을 감상한다 |
| ⑤ | **검색** | 빨리 찾고 싶다 | 전체 검색 | 모든 기억을 가장 빠르게 찾는다 |

### 방식과 화면의 관계

- **시간**과 **여행**은 같은 화면(여행기록)을 쓰되, **의도**가 다르다.
  - 시간: 연도·Timeline Chapter로 “언제”를 따라간다.
  - 여행: 여행(Story) 카드로 “그 여행”을 회상한다.
- **장소**는 지도·장소 축이다. 여행기록의 보조 정보가 아니다.
- **사진**은 감상이다. 분류·관리 UI가 우선이면 안 된다.
- **검색**은 축을 건너뛰어 **최단 경로**로 기억에 닿는다.

```
                    ┌─────────────┐
                    │    Home     │  출발점 (방식 선택)
                    └──────┬──────┘
           ┌───────────────┼───────────────┐
           │               │               │
     ① 시간 / ③ 여행    ② 장소         ④ 사진
           │               │               │
     ┌─────▼─────┐   ┌─────▼─────┐   ┌─────▼─────┐
     │  여행기록  │   │  방문지도  │   │   사진첩   │
     └─────┬─────┘   └─────┬─────┘   └─────┬─────┘
           │               │               │
           └───────────────┼───────────────┘
                           │
                    ┌──────▼──────┐
                    │ ⑤ 전체 검색  │  모든 축을 가로지름
                    └─────────────┘
```

## 3. 화면별 IA 역할

### Home — 출발점

- **역할**: 다섯 탐색 방식으로 연결되는 **현관**.
- **아님**: 정보를 많이 쌓아 두는 Dashboard.
- **목표**: “어떤 방식으로 기억을 찾을지” 선택하게 한다.
- **원칙**: 추천 한 점(Hero)으로 발견을 돕고, Preview로만 각 축에 보낸다.
- Home에 **오래 머무는 것이 목적**이 아니다.

### 여행기록 — 시간 · 여행

- **역할**: **시간**과 **여행** 탐색의 본진.
- **시간**: 연도는 Chapter. 스크롤로 인생의 흐름을 느낀다.
- **여행**: 여행은 Story. 대표사진이 먼저인 앨범 한 페이지.
- **아님**: 통계·랭킹 Dashboard.

### 방문지도 — 장소

- **역할**: **장소**를 따라 기억을 탐험한다.
- **목표**: “아, 여기도 갔었지”를 지도·장소 기억으로 만든다.
- **아님**: 지도 도구 그 자체. 마커보다 장소의 기억이 우선.

### 사진첩 — 사진

- **역할**: **사진**을 감상한다.
- **목표**: 사진이 가장 먼저, 가장 크게 보인다.
- **아님**: 파일 브라우저·일괄 관리 콘솔.

### 전체 검색 — 검색

- **역할**: 축을 고르지 않고 **모든 기억**에 가장 빨리 닿는다.
- **목표**: 장소명·태그·기간 등 기존 검색 수단으로 바로 회상/감상/지도로 이어진다.
- **확장**: 향후 AI 검색은 이 축의 능력 강화이지, 새 최상위 제품이 아니다.

## 4. 현재 내비 · 지원 화면 (변경하지 않음)

이 IA는 **메뉴 구조·Navigation·기능을 바꾸지 않는다.**  
기존 화면을 다섯 방식에 **매핑**한다.

| 현재 진입점 (예시) | IA상 위치 |
|---|---|
| Home | 출발점 |
| 여행기록 | ① 시간 · ③ 여행 |
| 방문지도 | ② 장소 |
| 사진첩 | ④ 사진 |
| 검색 (방문지도·Gallery 검색 등; V1 GNB에 전역「검색」메뉴 없음) | ⑤ 검색 |
| 설정 · 사진등록 · 미완성 추억 · 장소/태그 관리 | **지원(Support)** — 탐험의 본축이 아님 |

지원 화면은 탐험을 **가능하게 만드는 뒷단**이다.  
Home·본축 화면보다 앞에 두지 않는다.

---

## 5. 탐험 흐름 (의도)

기능 추가는 없다. **이미 있는 연결**을 IA 관점에서 이렇게 읽는다.

```
프로그램 실행
  → Home에서 방식 선택 (또는 추천 추억 발견)
  → 여행기록 / 방문지도 / 사진첩 / 검색
  → 필요 시 축 간 이동 (예: 여행 → 장소, 사진 → 지도)
  → Home으로 돌아와 다시 탐험
```

축 간 이동은 “다른 앱으로 점프”가 아니라 **같은 기억을 다른 방식으로 다시 보는 것**이다.

## 6. 확장 원칙 (NAS · 모바일 · 웹 · AI · 가족 공유)

IA의 다섯 축은 **클라이언트·저장소와 무관하게 유지**한다.

| 확장 | IA에서의 의미 |
|---|---|
| **NAS** | Storage 추상화. 탐색 방식은 동일, 파일 위치만 바뀜 |
| **모바일 / 웹** | 같은 다섯 축·같은 Home 출발점. 화면 밀도만 플랫폼에 맞게 |
| **AI 검색** | ⑤ 검색 축의 이해·추천 강화. 새 최상위 메뉴를 기본으로 만들지 않음 |
| **가족 공유** | 같은 탐험 방식 위에 **누구의 기억인가** 레이어가 추가됨. 축 자체는 유지 |

새 기능·새 화면을 넣을 때 질문:

1. 다섯 탐색 방식 중 **어디에 속하는가?**
2. Home의 출발점 역할을 **흐리지 않는가?**
3. 지원(관리) 기능이 탐험 본축보다 **앞에 나오지 않는가?**

---

## 7. 이 문서의 범위

### 한다

- 제품·화면·탐색 방식의 **역할 정의**
- 기존 내비와 IA의 **매핑**
- 향후 확장 시 **판단 기준**

### 하지 않는다

- 기능 추가
- UI 대규모 변경
- DB·메뉴·Navigation 구조 변경
- 새 화면 신설

구체 UI는 화면별 작업에서 `UX_PHILOSOPHY.md` + 이 문서를 기준으로 한다.

## 8. 체크리스트

IA·카피·내비 라벨·화면 우선순위를 검토할 때:

- [ ] 이 화면은 다섯 방식 중 **하나를 분명히** 담당하는가?
- [ ] Home이 Dashboard가 아니라 **출발점**으로 읽히는가?
- [ ] 여행기록이 **시간·여행** 탐험으로 읽히는가? (통계가 아닌가?)
- [ ] 방문지도가 **장소** 탐험으로 읽히는가?
- [ ] 사진첩이 **감상**으로 읽히는가?
- [ ] 검색이 **최단 경로**로 읽히는가?
- [ ] 관리/설정이 탐험 본축보다 **앞에 나오지 않는가?**
- [ ] 향후 NAS/모바일/AI/공유에도 **같은 다섯 축**으로 설명 가능한가?
