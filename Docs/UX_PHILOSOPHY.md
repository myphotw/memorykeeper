# MemoryKeeper UX Philosophy

> 사진 관리 프로그램이 아니라, **추억을 다시 떠올리는 공간**.

이 문서는 UI·카피·정보 우선순위의 **표현 원칙**을 고정한다.  
제품의 **탐색 구조·화면 역할(IA)** 은 `Docs/INFORMATION_ARCHITECTURE.md`가 우선한다.

**기능·메뉴·DB·Navigation·화면 구조는 이 문서만으로 변경하지 않는다.**

---

## 1. 제품 철학

MemoryKeeper는 사진을 **저장·정리하는 도구**가 아니다.  
사진을 통해 **잊고 있던 추억을 다시 만나는 공간**이다.

| 사용자가 느끼면 안 되는 감정 | 사용자가 느껴야 하는 감정 |
|---|---|
| 사진을 정리해야지 | 예전 여행 한번 볼까? |
| 파일이 몇 장이지? | 그때 찍은 사진 다시 보고 싶다 |
| 관리 대시보드 | 천천히 앨범을 넘기는 여유 |

키워드: **기억 · 따뜻함 · 여유 · 행복 · 발견**

---

## 2. 핵심 사용자 질문

모든 UI는 아래 질문에 **가장 쉽게** 답할 수 있어야 한다.

1. 2025년에 어디를 갔었지?
2. 일본은 몇 번 갔었지?
3. 금각사는 언제 갔었지?
4. 제주에는 몇 번 갔었지?
5. 그때 찍은 사진 다시 보고 싶다.

화면·카피·정보 우선순위는 이 다섯 질문을 기준으로 판단한다.

---

## 3. 다섯 가지 기억 탐색 방식 (IA 요약)

상세 정의는 `INFORMATION_ARCHITECTURE.md`를 본다.  
모든 주요 화면은 아래 중 하나를 담당한다.

| 탐색 방식 | 담당 화면 | UX에서 느낄 것 |
|---|---|---|
| **시간** | 여행기록 | 연도를 따라 인생을 돌아본다 |
| **장소** | 방문지도 | 어디를 갔는지 떠올린다 |
| **여행** | 여행기록 | 그 여행을 다시 살아본다 |
| **사진** | 사진첩 | 사진을 감상한다 |
| **검색** | 전체 검색 | 가장 빨리 찾는다 |

**Home**은 다섯 방식으로 이어주는 **출발점**이다. Dashboard가 아니다.

```
Home (발견·방식 선택)
   ├─ 시간 / 여행  → 여행기록
   ├─ 장소         → 방문지도
   ├─ 사진         → 사진첩
   └─ 검색         → 전체 검색
```

---

## 4. 화면별 UX 역할

### Home — 출발점 · 추천

- **역할**: 무엇을·어떤 방식으로 볼지 고르는 현관.
- **목표**: 추천 추억(Hero)으로 발견하고, Preview로 각 축에 들어간다.
- **하지 말 것**: 숫자·통계·관리 항목을 상단에 두기.

### 여행기록 — 시간 · 여행 (돌아보기)

- **역할**: 시간을 따라, 여행의 **기록과 패턴**을 돌아본다.
- **목표**: 「그때 어디를 갔었지」를 Insight·타임라인으로 한눈에 본다.
- **원칙**: 사진첩이 아니다. 대표사진을 크게 보여주지 않는다.
- **정보 구성**
  1. Memory Insight (최근 / 오래 안 간 곳 / 가장 멀리 / 많이 간 나라)
  2. 연도별 여행 타임라인 (Row)
  3. 간단한 여행 통계

### 방문지도 — 장소

- **역할**: 장소를 따라 기억을 탐험한다.
- **목표**: “아, 여기도 갔었지.”
- **원칙**: 지도 UI보다 **장소의 기억**이 우선.

### 사진첩 — 사진

- **역할**: 사진을 감상한다.
- **목표**: Grid에서 **사진 자체**가 가장 먼저, 가장 크게.
- **원칙**: 필터·툴바보다 사진이 우선.

### 검색 — 최단 경로

- **역할**: 축을 고르지 않고 기억에 바로 닿는다.
- **원칙**: 검색 결과가 다시 여행·장소·사진 감상으로 자연스럽게 이어지게 한다.
- **V1 GNB:** 전역「검색」메뉴는 제거. 방문지도 검색창 등으로 수행.

---

## 5. 공통 UX 원칙

1. **사진이 UI보다 먼저** 보인다.
2. **장소명·여행명**이 숫자·메타보다 먼저 읽힌다.
3. 여백을 충분히 두어, 천천히 둘러볼 수 있게 한다.
4. 업무/파일관리 프로그램처럼 보이지 않는다.
5. 강한 색·장식·과장된 감성 카피는 쓰지 않는다. 따뜻하되 담백하게.

### 정보 표현 기본 순서

```
대표사진
  → 장소 / 여행명
  → 기간 / 날짜
  → 사진 수
  → 세부 정보
```

---

## 6. 제품 전체 UX 체크리스트

리디자인·카피·레이아웃 검토 시 모두 **YES**여야 한다.

- [ ] 사진보다 UI가 눈에 띄지 않는가?
- [ ] 사용자가 기억을 떠올릴 수 있는가?
- [ ] 업무 프로그램처럼 보이지 않는가?
- [ ] 텍스트보다 사진이 먼저 보이는가?
- [ ] 화면이 추억을 감상하기에 편안한가?
- [ ] 핵심 질문 5가지 중 하나에 더 빨리 답할 수 있게 되었는가?
- [ ] 이 화면의 IA 역할(다섯 방식 중 하나)이 흐려지지 않았는가?

---

## 7. 변경하지 않는 것 (이 문서의 범위)

- 메뉴 구조: Home / 사진첩 / 방문지도 / 여행기록 (+ 설정). V1 GNB에 전역「검색」없음
- DB, 기능, Navigation, 사진 정리 로직
- 화면의 존재 자체와 기본 정보 구조

역할·의미의 정의는 `INFORMATION_ARCHITECTURE.md`와 이 문서가 고정한다.  
구체 UI는 화면별 작업에서 두 문서를 기준으로 진행한다.

---

## 8. 이후 작업에의 적용

| 화면 | IA 초점 | UX 초점 |
|---|---|---|
| Home | 출발점 · 방식 선택 | 추천 Hero · Preview만 |
| 여행기록 | 시간 · 여행 | Insight · 타임라인 · 통계(사진첩 아님) |
| 방문지도 | 장소 | 장소 기억 우선 |
| 사진첩 | 사진 | 감상 우선 Grid |
| 검색 | 검색 | 최단 경로 · 결과→회상 |

작업 시작 전에 **IA 역할**과 **이 문서 체크리스트**를 다시 확인한다.
